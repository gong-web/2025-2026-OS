## 🔬 实验概览

### Lab3: 中断与中断处理 ⭐ **当前重点**

#### 📖 实验背景

中断处理机制是操作系统的核心功能之一。本实验在已有的物理内存管理基础上，加入了对 **中断与异常** 的完整支持，并通过 **时钟中断** 来验证中断处理系统的正确性，使操作系统能够响应硬件事件。

#### 🎯 实验目标

1.  **深入理解 RISC-V 中断机制**: 掌握中断分类、特权级模式 (M/S/U) 及其切换，以及中断委托 (mideleg/medeleg) 原理。
2.  **实现上下文切换**: 编写汇编代码 (`trapentry.S`) 实现 `TrapFrame` 的保存与恢复，掌握 `sepc`, `scause`, `stval` 等关键 CSR 的使用。
3.  **实现中断处理程序**: 编写时钟中断处理程序，建立中断分发机制，掌握从硬件触发到软件响应的完整流程。

#### 🔑 核心技术要点

-   **中断入口点 (`trapentry.S`)**:
    -   通过 `SAVE_ALL` 和 `RESTORE_ALL` 宏精确控制所有通用寄存器和 CSR 的入栈和出栈。
    -   使用 `sscratch` 寄存器暂存 `sp`，实现高效的上下文切换。
    -   通过 `sret` 指令完成从 S 模式的安全返回。

-   **中断分发 (`trap.c`)**:
    -   在 `idt_init` 中设置 `stvec` 寄存器，将所有中断/异常指向 `__alltraps` 入口。
    -   `trap_dispatch` 函数通过检查 `scause` 寄存器的最高位，区分中断和异常，并分发给相应的处理函数。

-   **时钟中断处理 (`clock.c`, `trap.c`)**:
    -   通过 OpenSBI 的 `sbi_set_timer()` 接口设置下一次时钟事件。
    -   中断处理程序 `interrupt_handler` 响应 `IRQ_S_TIMER` 类型的中断，累加计数器，并周期性地打印信息，最终通过 `sbi_shutdown()` 关闭系统，验证了整个流程的正确性。

#### 📊 实验结果

系统成功启动后，能够稳定地周期性触发时钟中断，每 100 次中断打印一次 "100 ticks"，累计 10 次后自动关机，与预期完全一致，证明中断系统工作正常。

```

100 ticks
[qemu-system-riscv64: terminating via exit(0)]
```

1.  **环境要求**:
    -   OS: Linux 或 Windows + WSL2
    -   工具链: RISC-V GNU Toolchain
    -   模拟器: QEMU for RISC-V

2.  **编译与运行**:
    ```bash
    # 进入对应实验目录，例如 lab3
    cd lab3

    # 编译
    make

    # 在 QEMU 中运行
    ```

### Lab1: 系统启动与内核初始化
**目标**: 理解 RISC-V 平台从硬件复位到内核入口的完整启动流程。
**关键内容**:
- 分析 RISC-V 启动链 (0x1000 → 0x80000000 → 0x80200000)。
- 掌握 OpenSBI 固件与内核的交互。
- 实现栈初始化与内核入口点。

---

### Lab2: 物理内存管理
**目标**: 实现功能完备的物理内存管理系统。
**关键内容**:
- 实现了 First-Fit 和 Best-Fit 内存分配算法。
- 深入研究并完整实现了 **SLUB 分配器**，包含快速/慢速路径优化、CPU 本地缓存和批量分配机制，并提供了详尽的技术文档。
