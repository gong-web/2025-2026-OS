## 🔬 实验概览

### Lab5: 用户程序 ⭐ **当前重点**

#### 📖 实验背景

在实现了内核线程的基础上，Lab5 将进一步向上层扩展，实现**用户进程**的管理。通过引入用户态（User Mode）与内核态（Kernel Mode）的隔离，操作系统能够安全地加载并执行用户程序。本实验重点关注进程的生命周期管理（创建、执行、等待、退出）以及系统调用机制的实现。

#### 🎯 实验目标

1.  **加载用户程序 (`load_icode`)**: 解析 ELF 格式的可执行文件，建立用户内存空间，并伪造中断现场以切换至用户态。
2.  **父子进程复制 (`do_fork`, `copy_range`)**: 实现进程的内存空间复制，支持写时复制（Copy-on-Write, COW）机制以提高效率。
3.  **进程生命周期**: 完善 `do_execve`（执行新程序）、`do_wait`（等待子进程）、`do_exit`（进程退出）等核心系统调用。
4.  **系统调用机制**: 理解 `ecall`/`ebreak` 指令触发的异常处理流程，实现用户态到内核态的参数传递与服务分发。

#### 🔑 核心技术要点

-   **用户态切换 (`load_icode`)**:
    -   手动构建 `trapframe`，设置 `sstatus` 的 SPP 位为 0（用户态），SPIE 位为 1（开启中断）。
    -   设置 `sepc` 为程序入口，`sp` 为用户栈顶，通过 `sret` 指令完成“无中生有”的模式切换。

-   **内存复制与COW (`copy_range`)**:
    -   在 `fork` 时不直接深拷贝物理内存，而是将父子进程的页表项设为只读并共享同一物理页。
    -   当任一进程尝试写入时，触发缺页异常（Page Fault），内核再进行物理页复制并恢复写权限。

-   **进程维系与回收**:
    -   维护进程树结构（父子、兄弟指针），确保 `do_exit` 时正确托孤（re-parent）给 `initproc`。
    -   `do_wait` 负责回收僵尸进程（ZOMBIE）的资源，防止内存泄漏。

#### 📊 实验结果

系统成功加载并执行了用户态程序。通过系统调用（`SYS_fork`, `SYS_exec`, `SYS_yield` 等），验证了用户进程的创建、调度、内存隔离及退出机制的正确性。

### Lab4: 内核线程管理
**目标**: 实现内核线程（Kernel Thread）管理与调度，构建进程管理的基石。
**关键内容**:
-   **进程控制块 (PCB)**: 设计 `proc_struct`，维护进程状态与上下文。
-   **线程创建 (`do_fork`)**: 实现内核线程的创建与资源分配。
-   **调度与切换**: 实现 `proc_run` 与 `switch_to`，完成执行流的保存与恢复。

---

### Lab3: 中断与中断处理
**目标**: 建立完善的中断与异常处理机制，响应硬件事件。
**关键内容**:
-   **中断入口**: 编写 `trapentry.S`，利用 `sscratch` 实现用户栈/内核栈切换，保存 `TrapFrame`。
-   **中断分发**: 实现 `trap_dispatch`，根据 `scause` 区分中断与异常。
-   **时钟中断**: 利用 OpenSBI 接口设置定时器，实现了基于时间片的系统心跳。

---

### Lab2: 物理内存管理
**目标**: 实现功能完备的物理内存管理系统。
**关键内容**:
-   实现了 First-Fit 和 Best-Fit 内存分配算法。
-   深入研究并完整实现了 **SLUB 分配器**，包含快速/慢速路径优化、CPU 本地缓存和批量分配机制。

---

### Lab1: 系统启动与内核初始化
**目标**: 理解 RISC-V 平台从硬件复位到内核入口的完整启动流程。
**关键内容**:
-   分析 RISC-V 启动链 (0x1000 → 0x80000000 → 0x80200000)。
-   掌握 OpenSBI 固件与内核的交互。
-   实现栈初始化与内核入口点。
