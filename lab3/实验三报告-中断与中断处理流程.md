# 操作系统实验三报告：中断与中断处理流程

## 实验概述

### 实验背景

在完成了物理内存管理和页表机制之后，内核已经具备了最基本的内存支持。接下来，我们需要让操作系统能够与外部世界进行交互，并能够对硬件事件作出响应。因此在实验三中，我们将在最小可执行内核的基础上，加入对中断与异常的支持，并通过时钟中断来验证中断处理系统的正确性。

### 实验意义

中断处理机制是操作系统的核心功能之一。操作系统是计算机系统的监管者，必须能对计算机系统状态的突发变化做出反应，这些系统状态可能是程序执行出现异常，或者是突发的外设请求。当计算机系统遇到突发情况时，不得不停止当前的正常工作，应急响应一下，这需要操作系统来接管，并跳转到对应处理函数进行处理，处理结束后再回到原来的地方继续执行指令。这个过程就是中断处理过程。

## 实验目的

本次实验旨在通过实践深入学习和全面掌握 **RISC-V 架构下的中断处理机制**。实验的首要目标是理解 RISC-V 的核心中断知识，包括其完整的中断机制、特权级模式的划分以及中断委托机制的工作原理。其次，我们将聚焦于中断前后的**上下文环境保存与恢复**，具体来说，就是理解中断帧（TrapFrame）的结构，并通过汇编代码实践上下文切换机制，从而掌握关键寄存器的保存和恢复过程。最终，我们将实现对最简单的**断点中断和时钟中断**的处理，这包括编写和实现时钟中断处理程序，理解复杂的中断分发机制，并最终掌握从硬件触发到软件响应的完整中断处理流程。通过这些步骤，为后续更复杂的操作系统内核开发打下坚实的基础。

## 理论基础

### 中断概念

#### 中断机制

中断（interrupt）机制，就是不管CPU现在手里在干什么活，收到"中断"的时候，都先放下来去处理其他事情，处理完其他事情可能再回来干手头的活。

**中断的典型应用场景：**

1. **I/O设备中断**：CPU要向磁盘发一个读取数据的请求，由于磁盘速度相对CPU较慢，在"发出请求"到"收到磁盘数据"之间会经过很多时间周期。如果CPU干等着磁盘干活就相当于CPU在磨洋工。因此我们可以让CPU发出读数据的请求后立刻开始干另一件事情。等磁盘的数据取到了，磁盘给CPU一个"中断"，让CPU放下手里的事情来接受磁盘的数据。

2. **时钟中断**：为了保证CPU正在执行的程序不会永远运行下去，我们需要定时检查一下它是否已经运行"超时"。想象有一个程序由于bug进入了死循环，如果CPU一直运行这个程序，那么其他的所有程序都会因为等待CPU资源而无法运行，造成严重的资源浪费。我们需要CPU定时"打断"当前程序的执行，去进行一些处理，这通过时钟中断来实现。

#### 中断分类

在RISC-V架构中，中断和异常统称为trap，主要分为以下几类：

1. **异常(Exception)**：指在执行一条指令的过程中发生了错误，此时我们通过中断来处理错误。最常见的异常包括：访问无效内存地址、执行非法指令(除零)、发生缺页等。有的可以恢复(如缺页)，有的不可恢复(如除零)，只能终止程序执行
   
2. **陷入(Trap)**：指我们主动通过一条指令停下来，并跳转到处理函数。常见的形式有：通过ecall进行系统调用(syscall)、通过ebreak进入断点(breakpoint)
   
3. **外部中断(Interrupt)**：简称中断，指的是CPU的执行过程被外设发来的信号打断，此时我们必须先停下来对该外设进行处理。典型的有：定时器倒计时结束、串口收到数据等。外部中断是异步(asynchronous)的，CPU并不知道外部中断将何时发生

### RISC-V 权限模式

#### 特权级概述

在现代处理器中，系统通常会区分用户态（User Mode）和特权态（Supervisor/Kernel Mode）。用户态运行应用程序，权限有限，不能直接访问硬件和关键寄存器。特权态运行操作系统内核，可以控制硬件、管理内存和调度任务。

#### RISC-V 的三个特权级

1. **M 模式（Machine Mode）**：是RISC-V中最高的特权级，在M模式下，hart（硬件线程）对内存、I/O和底层功能有完全的控制权。默认情况下，所有的中断和异常都会首先进入M模式处理
   
   ，M模式是所有标准RISC-V处理器必须实现的特权级，通常用于处理器启动、底层固件（如OpenSBI）的执行。
   
2. **S 模式（Supervisor Mode）**：是支持现代类Unix操作系统的特权级。操作系统内核运行在S模式，它支持基于页面的虚拟内存机制，使得多任务和内存隔离成为可能。在Unix系统中，大多数系统调用和异常都在S模式下处理
   
3. **U 模式（User Mode）**：是最低的特权级，用户程序运行在U模式，只能执行普通指令。能直接访问硬件或执行特权操作，当用户程序需要操作系统服务时，必须通过系统调用（ecall指令）陷入到S模式

### 中断的路由：从默认路径到委托机制

#### 默认路径

在RISC-V架构中，中断与异常是构建一个健壮、可响应系统的基石。默认情况下，RISC-V遵循最保守的安全设计：所有中断与异常都会首先陷入最高特权级——M模式。M模式作为硬件的直接管理者，拥有最终控制权，此设计确保了系统的底层安全。

#### 委托机制

然而，对于运行现代操作系统的场景，让所有中断都经由M模式处理，会带来不必要的性能开销和灵活性限制。为解决此问题，RISC-V引入了中断委托机制。M模式可以通过设置两个关键寄存器，将特定的中断与异常处理权"下放"给S模式：

**mideleg (Machine Interrupt Delegation Register)**：负责委托中断。例如，将软件中断、定时器中断或外部中断委托给S模式。

**medeleg (Machine Exception Delegation Register)**：负责委托异常。例如，将用户态环境调用、非法指令、页错误等异常委托给S模式。

#### 中断处理路由

在ucore启动时，OpenSBI固件会进行初始化，将绝大部分S模式与U模式相关的中断和异常委托出去。现在，我们可以分场景审视一个中断的完整流程：

1. **U模式触发中断**：当用户程序执行ecall指令发起系统调用，或执行指令时发生页错误，该异常会被medeleg委托。硬件将直接陷入到S模式，而不再经过M模式。

2. **S模式触发中断**：内核自身在运行时也可能遇到两种性质不同的陷阱：
   
   被动陷入：例如设备I/O完成产生的外部中断，或内核代码触发的缺页异常

   主动陷入：当内核需要访问硬件特权功能时，它会主动执行ecall指令
   
3. **M模式触发中断**：某些与最底层硬件管理紧密相关的中断，通常不会被委托，始终在M模式内处理。

### S模式的中断处理框架

#### 中断向量表

一旦中断被路由到S模式，处理器便需要知道如何开始执行处理代码。RISC-V架构有个CSR叫做stvec(Supervisor Trap Vector Base Address Register)，即所谓的中断向量表基址。

stvec会把最低位的两个二进制位用来编码一个"模式"：

如果是00：说明更高的SXLEN-2个二进制位存储的是唯一的中断处理程序的地址

如果是01：说明更高的SXLEN-2个二进制位存储的是中断向量表基址，通过不同的异常原因来索引中断向量表

#### 关键寄存器

当我们触发中断，进入S模式进行处理前，硬件会自动为处理程序准备好一份详尽的上下文报告。这份报告由三个关键寄存器构成：

1. **sepc(Supervisor Exception Program Counter)**：自动保存了被中断指令的虚拟地址，回答了"事发时程序执行到了哪里？"的问题。是未来恢复执行的关键。
   
2. **scause(Supervisor Cause Register)**：记录了一个编码，精确指出了中断或异常的具体原因，例如，是用户态的系统调用，还是指令页错误？或者是外部设备中断？处理程序通过查阅此寄存器来辨别事件性质。
   
3. **stval(Supervisor Trap Value)**：提供了与异常相关的附加信息，是重要的"现场证据"，当发生缺页异常时，stval会存放导致失败的访存地址，当遇到非法指令时，它可能会记录该指令本身的内容

#### 使能与屏蔽

在S模式处理中断时，一个关键的设计抉择是中断的使能状态。sstatus(Supervisor Status Register)寄存器里面有一个二进制位SIE(supervisor interrupt enable)，数值为0的时候，如果当程序在S态运行，将禁用全部中断。

sstatus寄存器中还包含多个重要的控制位：

**SPIE（Supervisor Previous Interrupt Enable）**：记录进入S模式之前的SIE值

**SPP（Supervisor Previous Privilege）**：记录进入S模式之前的特权级

除了sstatus寄存器中的SIE控制位，还存在一个sie寄存器，即使sstatus.SIE为1，也可以通过sie寄存器屏蔽特定类型的中断。

#### 特权指令

在整个中断的生命周期中，特权指令扮演着流程控制器的角色：

1. **ecall**：主动发起trap的指令，行为高度依赖于执行它的当前特权级
2. **sret**：从S模式返回的指令，会同时恢复sepc和sstatus.SIE的状态
3. **mret**：从M模式陷阱中返回
4. **ebreak**：触发一个断点异常，通常用于调试

### 从U模式陷入S模式的完整流程

当一个用户程序运行在U模式时，可能因为某些原因陷入S模式：

1. **保存中断发生时的pc值**：保存在sepc寄存器中
2. **记录中断或异常的类型**：写入scause寄存器
3. **保存相关的辅助信息**：保存到stval寄存器
4. **保存并修改中断使能状态**：将sstatus.SIE保存到sstatus.SPIE中，并将sstatus.SIE清零
5. **保存当前的特权级信息**：将当前特权级保存到sstatus.SPP中，并切换到S模式
6. **跳转到中断处理程序**：将pc设置为stvec寄存器中的值

## 实验内容

### 项目组成

#### 硬件驱动层

1. **kern/driver/clock.c(h)**：通过OpenSBI的接口，可以读取当前时间(rdtime)，设置时钟事件(sbi_set_timer)，是时钟中断必需的硬件支持。
   
2. **kern/driver/intr.c(h)**：中断需要CPU的硬件支持，提供了设置中断使能位的接口（封装了一句RISC-V指令）。

#### 初始化

**kern/init/init.c**：需要调用中断机制的初始化函数

#### 中断处理

1. **kern/trap/trapentry.S**：中断入口点设置为这段汇编代码，这段汇编代码进行寄存器数据的保存和恢复，完成上下文切换。
   
2. **kern/trap/trap.c(h)**：分发不同类型的中断给不同的handler，完成上下文切换之后对中断的具体处理，中断处理初始化的函数，主要是把中断向量表(stvec)设置成所有中断都要跳到trapentry.S进行处理

### 执行流

#### 内核初始化函数kern_init()的执行流

1. 从kern/init/entry.S进入
2. 输出一些信息说明正在初始化
3. 设置中断向量表(stvec)跳转到的地方为kern/trap/trapentry.S里的一个标记
4. 在kern/driver/clock.c设置第一个时钟事件，使能时钟中断
5. 设置全局的S mode中断使能位 → 现在开始不断地触发时钟中断

#### 产生一次时钟中断的执行流

1. set_sbi_timer()通过OpenSBI的时钟事件触发一个中断，跳转到kern/trap/trapentry.S的__alltraps标记
2. 保存当前执行流的上下文，并通过函数调用，切换为kern/trap/trap.c的中断处理函数trap()的上下文，进入trap()的执行流。切换前的上下文作为一个结构体，传递给trap()作为函数参数
3. kern/trap/trap.c按照中断类型进行分发(trap_dispatch(), interrupt_handler())
4. 执行时钟中断对应的处理语句，累加计数器，设置下一次时钟中断
5. 完成处理，返回到kern/trap/trapentry.S
6. 恢复原先的上下文，中断处理结束

### 中断入口点实现

#### 初始化stvec寄存器

我们采用Direct模式，也就是stvec直接指向唯一的中断处理程序入口点，所有类型的中断和异常都会跳转到这里。

```c
void idt_init(void) {
    extern void __alltraps(void);
    /* Set sup0 scratch register to 0, indicating to exception vector
       that we are presently executing in the kernel */
    write_csr(sscratch, 0);
    /* Set the exception vector address */
    write_csr(stvec, &__alltraps);
}
```

#### 上下文切换机制

中断的处理需要放下当前的事情但之后还能回来接着之前往下做，对于CPU来说，实际上只需要把原先运行程序的寄存器保存好，处理完中断后再恢复回来就行了。

**TrapFrame结构体**：

## 代码实现

### 中断入口汇编代码

#### trapentry.S 分析

**SAVE_ALL 宏**：
```assembly
.macro SAVE_ALL
    csrw sscratch, sp
    addi sp, sp, -36 * REGBYTES
    # save x registers
    STORE x0, 0*REGBYTES(sp)
    STORE x1, 1*REGBYTES(sp)
    STORE x3, 3*REGBYTES(sp)
    # ... 保存所有通用寄存器
    
    # get sr, epc, badvaddr, cause
    csrrw s0, sscratch, x0
    csrr s1, sstatus
    csrr s2, sepc
    csrr s3, sbadaddr
    csrr s4, scause

    STORE s0, 2*REGBYTES(sp)
    STORE s1, 32*REGBYTES(sp)
    STORE s2, 33*REGBYTES(sp)
    STORE s3, 34*REGBYTES(sp)
    STORE s4, 35*REGBYTES(sp)
.endm
```

**RESTORE_ALL 宏**：
```assembly
.macro RESTORE_ALL
    LOAD s1, 32*REGBYTES(sp)
    LOAD s2, 33*REGBYTES(sp)

    csrw sstatus, s1
    csrw sepc, s2

    # restore x registers
    LOAD x1, 1*REGBYTES(sp)
    LOAD x3, 3*REGBYTES(sp)
    # ... 恢复所有通用寄存器
    
    # restore sp last
    LOAD x2, 2*REGBYTES(sp)
.endm
```

**中断入口点**：
```assembly
.globl __alltraps
.align(2)
__alltraps:
    SAVE_ALL
    move  a0, sp
    jal trap
    # sp should be the same as before "jal trap"

.globl __trapret
__trapret:
    RESTORE_ALL
    # return from supervisor call
    sret
```

#### 汇编代码详细分析

1. **保存上下文**：
   
   `csrw sscratch, sp`：将当前栈指针保存到sscratch寄存器
   
   `addi sp, sp, -36 * REGBYTES`：在栈上分配空间存储寄存器

   依次保存所有通用寄存器x0-x31
   
   保存控制状态寄存器（sstatus, sepc, sbadaddr, scause）
   
2. **调用C函数**：
   
   `move a0, sp`：将栈指针（即trapframe指针）作为参数传递

   `jal trap`：跳转到C语言的trap函数
   
3. **恢复上下文**：
   
   恢复控制状态寄存器
   
   恢复所有通用寄存器
   
   `sret`：从S模式返回

```c
void trap(struct trapframe *tf) {
    // dispatch based on what type of trap occurred
    trap_dispatch(tf);
}

static inline void trap_dispatch(struct trapframe *tf) {
    if ((intptr_t)tf->cause < 0) {
        // interrupts
        interrupt_handler(tf);
    } else {
        // exceptions
        exception_handler(tf);
    }
}
```

#### 时钟中断处理实现

**时钟中断处理核心代码**：
```c
void interrupt_handler(struct trapframe *tf) {
    intptr_t cause = (tf->cause << 1) >> 1;
    switch (cause) {
        case IRQ_S_TIMER:
            // 设置下次时钟中断
            clock_set_next_event();
            
            // 计数器加一
            ticks_count++;
            
            // 当计数器达到100时，输出"100 ticks"并重置计数器
            if (ticks_count == 100) {
                print_ticks();
                ticks_count = 0;  // 重置计数器
                print_count++;    // 打印次数加一
                
                // 当打印次数达到10时，关机
                if (print_count == 10) {
                    sbi_shutdown();
                }
            }
            break;
        // ... 其他中断类型处理
    }
}
```

#### 时钟驱动实现

**clock.c 关键函数**：
```c
void clock_init(void) {
    // enable timer interrupt in sie
    set_csr(sie, MIP_STIP);
    // 设置时钟中断
    clock_set_next_event();
    // initialize time counter 'ticks' to zero
    ticks = 0;
    cprintf("++ setup timer interrupts\n");
}

void clock_set_next_event(void) { 
    sbi_set_timer(get_cycles() + timebase); 
}

static inline uint64_t get_cycles(void) {
#if __riscv_xlen == 64
    uint64_t n;
    __asm__ __volatile__("rdtime %0" : "=r"(n));
    return n;
#else
    uint32_t lo, hi, tmp;
    __asm__ __volatile__(
        "1:\n"
        "rdtimeh %0\n"
        "rdtime %1\n"
        "rdtimeh %2\n"
        "bne %0, %2, 1b"
        : "=&r"(hi), "=&r"(lo), "=&r"(tmp));
    return ((uint64_t)hi << 32) | lo;
#endif
}
```

### 实现要点分析

#### 时钟中断实现逻辑

1. **初始化阶段**：在`clock_init()`中使能时钟中断，设置第一个时钟事件，初始化计数器。
   
2. **中断处理阶段**：每次时钟中断到来时，调用`clock_set_next_event()`设置下一次中断，增加`ticks_count`计数器。当计数器达到100时，调用`print_ticks()`输出信息，重置`ticks_count`，增加`print_count`。当`print_count`达到10时，调用`sbi_shutdown()`关机

#### 上下文切换关键点

1. **寄存器保存顺序**：先保存栈指针到sscratch，然后分配栈空间，保存通用寄存器，保存控制状态寄存器。
   
2. **函数调用约定**：将trapframe指针作为参数传递给trap函数，保证栈指针在函数调用前后一致。
   
3. **恢复顺序**：先恢复控制状态寄存器，再恢复通用寄存器，最后恢复栈指针。

#### 中断分发机制

通过检查`tf->cause`的最高位来区分中断和异常：最高位为1：中断；最高位为0：异常。然后根据具体的cause值分发到相应的处理函数。
